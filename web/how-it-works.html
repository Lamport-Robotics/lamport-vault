How it works

One key. One use. The chain keeps count.

A Lamport Vault is an account on Solana that moves funds only when it sees a hash-based signature. Hash-based signatures are the oldest post-quantum idea there is: every key signs exactly once, and the vault remembers which ones are gone.

01

Your 24 words become a tree of one-time keys.

The words are a standard BIP-39 phrase. From them the vault derives a Merkle tree: 1 024 one-time keys at the leaves, one 56-byte public key at the root. Only the root lives on chain.

LMS, RFC 8554, SHA-256 throughout. The derivation is published so any wallet can rebuild the same tree.

02

Deposits are ordinary transfers.

The vault's address is derived from the first key and never changes, not even when the key rotates. Any wallet or exchange can send to it. Nothing on the way in needs a post-quantum signature.

03

To withdraw, sign somewhere the internet can't reach.

The vault page prepares a small request: what to send, where, which key number, until when. You carry it to the cold signer, a single file that runs with the network off, type the words, and bring back a signature. Paste, file or QR; the words never touch an online device.

Signing on this device is possible for small amounts. The page says so every time.

04

The chain verifies it and marks the key spent.

The program recomputes about a thousand SHA-256 hashes, checks the key number against the vault's bitmap, sets the bit, then moves the funds. Since Solana's 4 KB transactions, all of it fits in one transaction. A signed request is valid for at most a day.

05

When a key runs low, rotate in place.

The last key of every generation can only be spent on installing a fresh one at the same address. The vault keeps a record of every key it has ever used and refuses to go back; signatures from an earlier generation are refused by construction. A closed vault leaves a permanent marker so its address can never be reopened.
